# ORIGYM 内容写作与排版

把内容做得可信、好读、有明确视觉判断，同时保留 Signal Desk 的版本与审批边界。

## 输入

先读取当前内容版本、内部证据表、平台配置、已有素材说明和品牌约束。信息不足时保留 `null` 或列为人工核对项；不要用常识补写人物、数字、经历、结果、门店能力或账号表现。

研究证据、媒体观察、社区故事、品牌事实和编辑判断必须保留各自类别。公开社区帖子不能改写成会员或用户亲口反馈。

## 路由

- 所有任务先读 [editorial-taste.md](references/editorial-taste.md)。
- 每日、过去 24 小时、选题搜集、内容雷达、健身房故事或从选题继续形成内容时，必须读 [daily-health-radar.md](references/daily-health-radar.md)。默认每日自动化只运行 `radar-only`；只有调用方明确选择候选或配置 `develop-lead`，才继续生成评审稿。
- 公众号或小红书任务涉及写作、改稿、标题或终稿审阅时，必须读 [chinese-copy.md](references/chinese-copy.md)，并在平台改写后完成真人感与来源回归检查。
- 公众号或小红书任务产生、修改或审阅文本时，必须读 [reader-reflection.md](references/reader-reflection.md)，在平台初稿后完成读者视角反思与建议采纳记录。
- 公众号写作或排版读 [wechat.md](references/wechat.md)。
- 小红书写作、分页、封面或组图规划读 [xiaohongshu.md](references/xiaohongshu.md)。
- 公众号或小红书任务涉及选择、生成、重生成或审阅配图时，必须在生成前读 [image-prompts.md](references/image-prompts.md)，并用其中的质感 QA 检查最终项目文件。
- 同一母题做双平台时，两份平台参考都读；共享证据和边界，分别重写标题、开头、结构、视觉任务与行动。

## 工作方式

1. 如果是每日雷达，先固定检索窗口和时区，分别搜集研究、专业解读、社区故事与健身房行业信号；不足时明确返回“本轮无足够候选”，不为了日更凑数。
2. 如果已选择候选，写一段简短的内容设计判断：目标读者、唯一核心判断、证据强度、内容类型、声音和视觉语言。
3. 为每个段落或页面声明它独立承担的信息任务。删掉不改变理解的重复单元。
4. 完成来源约束下的平台初稿，再以目标读者的处境通读全文，记录可能的感受、理解断点、信任风险和行动阻力。
5. 将读者建议逐项标为采纳、部分采纳或不采纳并说明理由。写作或改稿任务直接应用合适建议；只读审阅任务仅给出最小修改建议，不覆盖正文。
6. 对采纳后的文本重新做来源与真人感回归，再决定图片、卡片、列表或留白；版式不替内容制造结论。
7. 通过现有评审 renderer 生成手机可见的预览，检查真实文字、真实素材和实际画幅。截图只是证据，不能替代逐项判断。
8. 输出建议、采纳记录、缺口和待确认项。

## 输出契约

advisory 输出至少包含：

- 雷达阶段绑定检索窗口、时区、规范化候选集 SHA、Skill 仓库 commit 和本适配器规则 SHA；进入创作阶段后绑定内容 SHA、实际评估语料 SHA、上游 Skill 仓库 commit 和本适配器规则 SHA。
- 使用的平台、来源分类和当前画幅。
- 最多 3 个有明确差异的标题方向；标题、封面文字和开头分别承担不同任务。
- 公众号段落结构或小红书逐页信息任务与视觉任务。
- 读者视角反思：目标读者处境、可能感受、理解断点、行动阻力，以及建议的采纳、部分采纳或不采纳记录。
- 按 `blocker`、`important`、`suggestion` 分类的发现；每条包含位置、可观察证据和最小修改建议。
- 未解决的来源、事实、素材、可读性或平台复核项。
- `releaseDecision: null`。

不要输出“可发布”“已批准”“预计表现”或虚构指标。不要调用发布、登录、外部图片获取或 CAPTCHA 流程。Skill 不读写 SQLite，也不直接写 Z 盘交付目录；只有可信编排器可以在契约检查后把雷达、评审稿和 advisory 记录保存到 Signal Desk SQLite 与固定输出目录。任何来源、正文、配图、模板或 render 变化都必须使旧批准失效。
