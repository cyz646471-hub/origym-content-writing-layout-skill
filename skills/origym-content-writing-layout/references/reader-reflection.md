# 读者视角反思与建议采纳

## 目的

平台初稿完成后，暂时放下编辑者和研究解读者的身份，从目标读者的真实处境通读全文。找出读者可能在哪里愿意继续读、开始怀疑、觉得被说教、看不懂或不知道下一步做什么，再把合适建议落实到文本。

这是一项内部 advisory 检查，不是虚构用户研究。不要把模拟感受写成读者反馈、访谈结论、账号数据或效果预测。

## 读者站位

只使用内容设计中已有的目标读者和处境，例如“工作日午餐主要在单位周边解决的上班族”。不要补姓名、职业细节、家庭经历、健康结果或引号内的假想评价。

通读时检查：

- 第一感受：标题与开头会带来好奇、信任、被理解、焦虑、被责备还是夸张感。
- 理解成本：核心判断能否用一句自然中文复述；术语、数字、研究设计或转折是否造成停顿。
- 相关性：读者能否看见自己的情境；海外研究、专业人群或特殊政策是否被直接套到本地生活。
- 信任风险：标题承诺是否超过正文；建议是否偷偷扩大为因果、处方、效果或品牌能力。
- 行动阻力：结尾动作是否具体、低门槛并处于读者可控制范围；结构性问题是否被重新推回个人承担。
- 情绪余味：读完是更清楚、更从容，还是被制造了新的及格线、羞耻、恐惧或无力感。

公众号与小红书分别反思。小红书还要检查逐页推进、封面承诺和手机阅读负担；公众号还要检查研究段落是否过密、结尾是否像总结报告。

## 建议与采纳

每条建议记录以下内容：

- `readerEvidence`：引发反应的具体标题、句子、段落或页面。
- `likelyResponse`：目标读者可能产生的感受或理解问题，明确这是模拟判断。
- `recommendation`：最小且可执行的文本调整。
- `decision`：`adopt`、`partial` 或 `reject`。
- `rationale`：为什么这样决定，包括来源、声音、篇幅和平台取舍。
- `appliedLocation`：采纳后改到哪里；未采纳则为 `null`。

符合以下条件时优先采纳：提高理解、信任、相关性或行动可行性，并且不新增来源外的人物、数字、经历、结果或因果结论。

建议方向有价值但会扩大结论、改变声音或挤掉必要边界时，只采纳其中安全的部分。需要虚构故事、制造焦虑、强化绝对标题、删除关键限制或承诺表现的建议应拒绝。

反思不是迎合。读者可能希望更短、更确定或更刺激，但不能因此删掉会改变结论的证据边界，也不能用“读者会喜欢”代替来源判断。

## 应用后回归

采纳后重新通读标题、开头、核心证据、建议和结尾：

1. 核对事实、判断、推断和建议分类，确认没有新增主张。
2. 确认修改确实解决了对应阅读问题，不只是换同义词。
3. 以同一读者站位再读一次；仍然存在的阻力进入未解决项。
4. 文本、标题或页面发生变化后更新内容 SHA，并使旧批准失效。

反思与采纳记录默认留在内部编辑说明或 advisory 结果中，不混入公开正文。只有用户明确要求展示反思过程时，才在交付说明中简要呈现。
