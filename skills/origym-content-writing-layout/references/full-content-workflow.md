# 小红书完整内容工作流

## 模式

- `radar-only`：没有确定选题或明确要求每日选题时，只产出候选，不写正文、不生图。
- `develop-lead`：用户已经给出方向或选择候选时，完成意图、补证、文案、摄影编辑首页／内页成图、持续复核和 Z 盘评审包，停在 `FINAL_APPROVAL_REQUIRED`。
- `release-current`：只对已经明确批准的当前绑定生成本地最终包和人工发布清单，不操作外部平台。

用户已经给出主题时直接使用 `develop-lead`。公众号、独立漫画、旧通用小红书 renderer 和旧视觉模板均不进入本流程。

## 绑定与状态

当前版本至少绑定：

- 意图 brief 和来源映射 SHA；
- 标题、逐页文案、发布正文和 hashtags SHA；
- 图片提示词与实际源图 SHA；
- 资产清单 SHA；
- 固定模板、生成方式和实际原生画布；
- 读者/真实性复核与 QA；
- Skill 版本或 tree SHA。

任何来源、文案、图片、模板或生成方式改动都使之前批准失效。缺少明确批准时，`releaseDecision` 保持 `null`。

## 1. 意图确定

在 `intent-brief.md` 冻结：

- 用户要解决的具体问题；
- 目标读者及其当下处境；
- 读完只需记住的一句判断；
- 教程、知识解释、清单或其他内容类型；
- 语气、健康边界和需要避免的表达；
- 标题、页数、图片、排版和 tags 等交付；
- 用户当前补充的模板、人物、服装、色板与画幅；
- 仍需核对而不能推断的项目。

只对会改变选题或成品形态的缺口提问，其他安全细节用明确假设推进。

## 2. 选题信息补充

1. 用 `rg` 在 `Z:/Projects/chi-papers/04-健康情报` 的索引、每日简报、主题和来源笔记中查相关材料。
2. 查看最新每日健康简报是否提供新研究、相邻问题或读者语言；没有相关内容就跳过。
3. 使用网络检索核验当前权威来源。训练、营养、健康和器械内容优先论文、专业指南、官方机构或第一方产品资料。
4. 形成来源表：`sourceId｜URL/本地笔记｜日期｜来源类型｜支持主张｜限制｜使用位置`。
5. 社区讨论只用于痛点、常见困惑和表达方式，不证明效果、不冒充 ORIGYM 会员故事。

搜索只补齐核心判断所需事实。海报可直接教学不显示证据，但内部研究文件保留完整映射。

## 3. 文案写作

交付：

- 首选标题 1 个；
- 真正不同的备选标题不超过 2 个；
- 每页的信息任务、视觉任务和真实中文；
- 发布正文；
- 6–10 个准确 hashtags；
- 图片顺序和替代文字。

标题负责搜索与处境，页面负责教学，发布正文负责可信进入；三者不要完整复读。写作时持续使用 `chinese-copy.md` 和 `reader-reflection.md`，删掉汇报腔、机械排比、假口语、重复总结和来源外的第一人称经历。

文案不制造身材或年龄焦虑，不用“白瘦幼”、固定周数必成、局部减脂或体重及格线刺激互动。人物的本命感、力量感和少女野心通过选择与行动表达，不堆口号。

## 4. 图片生成

1. 每张图先写用途、要看懂的动作/关系、场景、构图、人物、器械、原生画幅和禁止项。
2. `awesome-gpt-image-2` 只选择最接近的构图/表现参考；不得带入其他视觉系统。
3. `imagegen` 实际生成或编辑。多个页面可并行或一次生成，但逐张验收。
4. 文案锁定后直接生成照片与真实中文排版一体的完整页面，逐字校对标题、编号、组次和说明。
5. 需要稳定人物或器械时才输入参考图，并明确只继承身份或结构。
6. 保留工具返回的原生尺寸，不改成 1080×1440，不拉伸、裁切或放大。

人物固定为成年中国女性、自然高马尾、白色圆领短袖训练上衣、浅灰训练长裤和包头训练鞋；自然松弛、健康有力、目光进取。拒绝幼态大眼、媚态摆拍、夸张腰臀和过度健美。

## 5. 最新摄影编辑首页／内页

只使用项目 `docs/ORIGYM-XIAOHONGSHU-COVER-INNER-TEMPLATE.zh-CN.md` 定义的结构与视觉：

- 默认 1 张首页＋5 张内页；
- 暖白高留白、炭黑中文衬线大标题、浅米色圆角信息区和杏橙手绘标注；
- 明亮自然的 ORIGYM 专业健身房实拍；
- 内页照片与步骤、动作、判断或清单信息可左右对换；
- 页面保留系列标签、标题、副标题、必要参数、`ORIGYM TIP` 和品牌页脚。

旧 3×2 固定六宫格、半写实轻插画、鸭舌帽人物、旧通用小红书模板、Signal Poster、Studio Journal、虚影和解剖图均退出生产路线。用户对当前主题明确提出的新布局优先。

用 `imagegen` 直接输出照片与中文排版一体的逐页 PNG；不要求单独照片或 HTML/CSS renderer。检查原生画布、逐字中文、文字边界和遮挡。

## 6. 持续内容复核

| 节点 | 必查项 |
|---|---|
| 意图/证据 | 用户目标是否被替换；主张是否有来源；研究、社区和编辑建议是否分开 |
| 文案 | 目标读者是否看得懂；标题是否过度；是否有 AI 模板腔；行动是否可执行 |
| 图片提示词 | 单页单任务；逐字文案、人物、动作、器械、接触点和参考图角色是否明确 |
| 每张成图 | 人体比例、关节方向、动作阶段、握点/落脚点、机器连接、帽檐、伪字、品牌和水印 |
| 最终排版 | 中文、编号、顺序、遮挡、溢出、原生尺寸、资源、控制台和整组节奏 |

人体、动作或器械关键结构失败即为 blocker，重做对应资产。不能用裁切、箭头、文字或遮挡掩盖。

每条建议记录 `readerEvidence`、`recommendation`、`decision: adopt|partial|reject`、理由和应用位置。内部模拟判断不得写成真实用户反馈或预计表现。

## 7. Z 盘素材管理

默认写入：

```text
Z:/内容产出输出/
├── drafts/origym/YYYY-MM-DD-<topic>/
│   ├── intent-brief.md
│   ├── research-and-content.md
│   ├── xiaohongshu-copy.md
│   ├── reader-reflection.md
│   ├── prompts/image-prompts.md
│   ├── qa-report.md
│   ├── asset-manifest.json
│   └── README.md
├── assets/origym/womens-fitness-guide/<topic>/
└── exports/xiaohongshu/
    ├── review/<topic>/
    └── final/<topic>/
```

评审 README 把“先看成品”放最前，列出图片顺序、标题、发布正文、hashtags、QA、当前状态和未解决项。所有源图、终稿和关键文档记录 SHA-256。

## release-current

只在用户明确批准当前来源、文案、资产、模板、生成方式和 QA 绑定时：

1. 重新计算 SHA；
2. 复制当前已批准的逐页成图到 final；
3. 运行图像尺寸、逐字目视和文件校验；
4. 写入 Z 盘 `exports/xiaohongshu/final/<topic>/`；
5. 生成手动上传、平台预览和发布清单。

外部登录、上传和点击发布由负责人完成。只有负责人提供公开 URL/内容 ID 和发布时间后才能记录发布结果；未知字段保持 `null`。
